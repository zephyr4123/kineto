# AGENTS.md — kineto

kineto is a video studio for coding agents, built on [Remotion](https://www.remotion.dev).
**This repository is itself the Remotion project.** Every video lives in `videos/<id>/`,
and everything that is not creative code (records, assets, renders) goes through the `./kineto` CLI.

## First run

```bash
npm install
./kineto setup     # installs the official Remotion agent skills, syncs generated files
./kineto doctor    # every check should be ✓ (warnings tell you what to run)
```

## Make a video (the golden path)

```bash
./kineto new <id> --title "<title>"     # scaffolds videos/<id>/ from templates/blank and registers it
./kineto asset add <file|url> --license <spdx> --to <id> --as <alias>   # only if you need media
./kineto studio <id>                    # preview just this video; keep it open while you work
./kineto check                          # must pass before you say you are done
./kineto render <id>                    # only when the user asks for the file
```

`<id>` is kebab-case (`corner-hit`). `./kineto help` lists every command; `./kineto <command> --help` shows options.
`./kineto studio` without an id opens every video; with an id it is isolated from other videos' errors and missing assets,
and `./kineto render` always bundles only the video it renders.

## Where things live

```
videos/<id>/                 one directory = one video
  compositions.tsx    ✍️     every <Composition> of this video: the full video + one per scene
  Video.tsx           ✍️     the timeline: only arranges scenes (<TransitionSeries>/<Series>)
  scenes/*.tsx        ✍️     one scene per file
  components/*.tsx    ✍️     components only this video uses
  video.json          🔒     title / status / tags / asset links      → ./kineto new | update | asset add
  renders.jsonl       🔒     render history (append-only)             → ./kineto render
  assets.gen.ts       🔒     typed asset paths                        → ./kineto sync
assets/manifest.jsonl 🔒     asset library: hash, license, author, source (append-only)
src/                  🔒     Remotion entry; registry.gen.tsx is generated by ./kineto sync
engine/               ✍️     building blocks shared by 2+ videos
templates/            ✍️     starting points for ./kineto new
cli/  kernel/                the CLI and its logic (TypeScript run directly by Node, no build step)
```

✍️ = creative zone, write freely. 🔒 = controlled zone, **never edit by hand**: change it through the CLI.
`./kineto check` (run by CI) catches hand edits that break consistency — invalid records, stray or misnamed
compositions, stale generated files, corrupted stored assets. Commands that change records take a repository lock,
so running several at once is safe.

## Rules

1. **New videos only via `./kineto new`.** Never run `create-video` or scaffold a new Remotion project. This repo is the project.
2. **Composition ids** are JSX string literals equal to `<id>` or starting with `<id>-` (e.g. `corner-hit-intro`) —
   no `{...spread}`, no computed ids — and `<Composition>` / `<Still>` appear **only** in `videos/<id>/compositions.tsx`.
3. **Media only via `./kineto asset add`, always with `--license`.** Then use it as `staticFile(assets.<alias>)`
   with `import { assets } from "./assets.gen"`. Do not put files in a `public/` folder or import binaries.
   No license, unknown provenance → it does not go in. Prefer generating media yourself (record how in `--description`).
   To reuse an asset in another video, `./kineto asset link <asset-id> --to <id> --as <alias>` (ids: `./kineto asset list`).
   To correct a recorded license or author, `./kineto asset update <asset-id> --license <license>` — never edit the manifest.
4. **Export via `./kineto render`, not `npx remotion render`.** Only `./kineto render` stores the file and records
   the render (git sha, codec, Remotion version) in `renders.jsonl`.
5. **Remotion packages share one exact version** (see `package.json`). Add new ones with
   `npm install --save-exact @remotion/<pkg>@<that version>`; `./kineto doctor` checks this.
6. **Promote to `engine/` on second use.** A component starts in `videos/<id>/components/`; move it to `engine/`
   only when a second video needs it.

## Writing Remotion code

Follow the official Remotion skills (`remotion-best-practices` routes to the rest), installed by `./kineto setup`.
They win on *how to write Remotion code*; this file wins on *where things go and how they are recorded*.
Things that bite:

- Animate only with `useCurrentFrame()` + `interpolate()`/`spring()`. CSS transitions and animation classes do not render.
- Remotion renders frame by frame: everything must be a pure function of the frame. Use `random(seed)`, never `Math.random()`.
- Changing a scene's `durationInFrames` in `Video.tsx` (in code or by dragging in Studio) does **not** update the
  full video's `durationInFrames` in `compositions.tsx`. Update it yourself.
- Fonts: register the font file with `./kineto asset add` and load it with `@remotion/fonts`, so renders need no network.

## CLI contract

- Output is JSON when stdout is not a terminal (or with `--json`): results `{"ok":…,"command":…,"data":…}` on stdout,
  errors `{"ok":false,"error":{"code","message","hint"}}` on stderr. `ok` is `false` whenever the exit code is not 0
  — e.g. a failing `check` prints its report in `data` with `ok:false`.
- Exit codes: `0` success · `1` error, or a check that did not pass · `2` usage error (options go after the command).
- Errors carry a stable `code` and a `hint` with the next step. Read the hint before trying something else.

## Before you say "done"

```bash
npm run verify     # typecheck + lint + unit tests + ./kineto check
```

If you rendered, report the path and the `renders.jsonl` record, not just "rendered successfully".
